# 接管现有插件

人们因各种原因停止开发自己的插件。与其让这些插件停滞不前，我们鼓励人们将其列出，供其他更活跃的开发者接手。

在接管插件时，您承诺将负责所有未来的开发工作，并确保插件（及您本人）遵守所有[插件指南](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/)。

[alert]并非所有请求都会获得批准，即使审核通过也是如此。[/alert]

## 插件接管流程

有两种方式可以接管插件。

1. 直接联系开发者，对方同意后将您添加为维护者
2. 请求插件审核团队协助接管

既然您正在阅读本文，很可能正在采用第二种方式，请继续阅读下文。您需要完成本文列出的**所有**步骤。

### 1. 检查插件状态

如果插件处于开放和活跃状态，请先自行进行全面审查。确保您对长期维护代码感到舒适且有能力。

如果插件因**未使用**而被关闭，您可以跳过后续步骤，直接发送邮件至 `plugins@wordpress.org`，并附上您提议的插件版本。

如果插件因安全问题被关闭，我们要求**所有**这些问题都必须得到解决。因此，请全力以赴，证明您有动力发现并修复这些问题。

已关闭的插件被接管的可能性**较低**，因为其关闭原因可能更为复杂和棘手。例如，如果插件因许可问题被关闭，我们可能无法为除许可持有者之外的任何人重新开放它。

较大的插件（10万用户或更多）被接管的可能性也较低，因为其用户基数不容小觑，我们需要确保您确实有能力管理如此规模的插件。

### 2. 联系原始开发者

您**必须**尝试联系原始开发者，因为他们可以[授予您插件访问权限](https://developer.wordpress.org/plugins/wordpress-org/plugin-developer-faq/#plugin-ownership)。我们建议尝试：

- 发送电子邮件
- 在插件支持页面留言
- 在 GitHub 上提交 issue

我们希望您尽一切合理努力联系他们。如果插件页面显示该插件没有活跃的开发者，那么您可以直接进行下一步。

如果您**确实**联系到了开发者，请要求他们[将所有权转移给您](https://developer.wordpress.org/plugins/wordpress-org/plugin-developer-faq/#plugin-ownership)。他们可以自行完成此操作，完成后您即可管理该插件。如果他们遇到问题，请让他们通过电子邮件联系插件团队，我们将提供协助。

如果无法联系到开发者，或者他们没有回复，请继续执行步骤 3。

### 3. 更新代码

即使插件是由开发者直接提供给你的，你也必须从上到下审查代码，以确保其安全、可靠，并符合我们当前的[指南](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/)。

你的更新必须包括编辑 readme 文件，以记录新的所有权（最好注明生效时间），移除所有指向原开发者网站/支持资源的链接，并更新版权信息以包含你。请记住，版权是累积的。你需要保留原有的版权信息，并添加你自己的。

如果你的插件是一次重大升级，你_必须_提供升级路径。仅仅想要一个名称/别名并不足以成为接管插件的充分理由。我们非常重视我们的用户，务必不惜一切代价避免因你的升级破坏他们现有网站而损害他们对我们的信任。

请记住，你需要_增加_版本号，以便用户收到升级到新版本的提示。

### 4. 提交代码以供审核

如果仍无法联系到原开发者，您需要向插件审核团队寻求帮助。

完成代码更新后，请发送邮件至 `plugins@wordpress.org`，说明您尝试联系原开发者的方式，并附上打包为 zip 的代码。若无法通过邮件发送 zip 文件，可将代码上传至文件服务（如 Google Drive、Dropbox 等）或提供代码仓库链接（如 Github、Bitbucket 等）。请确保链接是公开的！

收到您提交的 zip 格式代码后，我们将进行审核和测试。此时，您将进入一个**常规**审核流程。也就是说，我们会像对待任何新插件一样，对整个插件的安全性和规范进行全面检查。即使这些问题在原插件中就已存在，您也需要修复它们。

在此阶段，部分插件可能被确认存在安全漏洞。根据问题的性质，我们可能会关闭这些插件，同时您需要承诺不公开披露这些问题。

### 5. 联系原开发者

当我们认为代码符合要求，且您有能力以符合我们指导方针的安全方式持续维护该特定插件时，我们将代表您联系原开发者，提供您的信息并说明您希望接手开发。

我们会尽力确保原插件作者收到通知，但有时这确实无法实现。

### 6. 耐心等待

我们给予原开发者 30 天（1 个月）的时间来回复我们的询问。如果他们回复并拒绝请求，我们将尊重他们的决定，并要求您将插件转换为分叉版本。我们尽力像尊重您作为开发者一样尊重他们，并尊重他们对其作品的意愿。

如果他们批准，我们将协助将插件转移到您的账户。

如果他们未回复，而您已走到这一步，我们很可能会将插件转移给您。

### 7. 更新插件

为了*安全地*更新插件，我们将在添加您之前关闭它。然后您需要通过 SVN 进行更新。完成后，我们会再次检查所有内容是否正确并重新开放。该插件现在将归您所有。

## 常见问题

### 旧的评论/支持帖子会被删除吗？

不会。你将继承所有好的和坏的内容。

### 我是否需要保留原开发者？

不需要。你可以（事实上也应该）撤销任何未积极参与插件维护者的提交权限。但根据版权限制，你必须在代码中保留他们的署名。我们建议你仍将其列为贡献者。

### 原开发者已故，这会影响什么吗？

是的，但并非如你所想。你（显然）可以跳过先向他们请求许可的步骤，但我们实际上会联系开发者的同事和团队，询问他们是否愿意继续维护该插件。在某些情况下，开发者会要求我们在其去世后永久关闭他们的插件。我们尊重他们的意愿。

### 为何我的请求被拒绝？

当我们拒绝插件接管申请时，通常出于以下原因：

- 申请开发者不具备我们认定的插件所需经验
- 所申请插件被认定为高风险
- 现有开发者是拥有商标权的公司或法律实体
- 插件存在法律问题导致无法转移
- 申请开发者存在多次违规记录
- 原始开发者要求我们拒绝转移

如果我们认为不宜移交插件，将尽快通知您。

极少数情况下，插件已移交新所有者但尚未部署代码。通常，若被告知特定插件不可接管，往往存在长期历史问题阻碍我们批准接管。此类情况下，我们建议您以分叉形式提交自己的插件版本。
